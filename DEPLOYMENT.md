# Первый опыт — подготовка к новому домену

## Перед запуском

1. Домен проекта: `первыйопыт.рф`. В `server/.env` используйте IDN/Punycode origin `SITE_URL=https://xn--b1afnubedu1fd.xn--p1ai` (без `/` в конце). В браузере домен будет отображаться кириллицей.
2. Создайте `.env` из `.env.example` и задайте уникальные пароли/секреты.
3. Смените PostgreSQL пароль, Resend API key и пароль администратора: старый архив содержал действующий `.env`, поэтому старые секреты нужно считать скомпрометированными.
4. Настройте DNS и TLS-сертификат для нового домена. В production обязательно HTTPS.
5. Настройте DNS A/AAAA для `xn--b1afnubedu1fd.xn--p1ai` и выпустите TLS-сертификат именно для этого домена. Не включайте `www`, пока отдельно не настроите его DNS, сертификат и редирект.
6. Укажите внешний IP администратора в `ADMIN_ALLOWED_IPS` (несколько адресов через запятую). Если сервер за reverse proxy, задайте корректное `TRUST_PROXY_HOPS`.
7. Настройте TOTP в приложении-аутентификаторе и внесите Base32 secret в `ADMIN_TOTP_SECRET`. Администратор вводит шестизначный код на странице входа.
8. В Resend подтвердите домен отправителя и установите `MAIL_FROM` на подтверждённый адрес.
9. Установите зависимости и запустите миграции/сервер: `cd server && npm ci && npm start`.

## Изменения в этой версии

- Брендинг в интерфейсе и письмах изменён на «Первый опыт».
- Canonical/SEO ссылки формируются из `SITE_URL`.
- Сессия хранится в HttpOnly cookie; в production cookie имеет `Secure` и `SameSite=Strict`. Браузерный код больше не хранит session token в localStorage.
- Ограничение входа — 5 попыток за 15 минут на IP/email с ответом HTTP 429.
- Добавлены защитные HTTP-заголовки, строгая политика same-origin и проверка Origin/Referer для изменяющих запросов.
- Страница администрирования и API администратора закрыты allowlist IP; вход администратора требует TOTP 2FA.
- Размер PDF-загрузок ограничен 10 МБ; JSON body имеет предел для base64-передачи, при этом сервер отдельно проверяет размер файла.
- Ошибки сервера не раскрывают внутренние детали в production.

## Важно

Это усиление базовой защиты, а не полноценный независимый аудит безопасности. Перед открытием сайта проведите тестирование на production-подобном стенде, настройте резервные копии PostgreSQL, мониторинг, TLS на reverse proxy и ротацию секретов. DAU не подключён: уточните, имеется ли в виду внутренняя метрика Daily Active Users, Яндекс Метрика, Google Analytics или конкретный сервис.
